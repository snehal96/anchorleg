Your agent hit 92%. The task kept going.

anchorleg runs your Claude Code, Codex and Antigravity tasks in the background and watches every account's 5-hour and weekly limits. When one runs low, it pauses at a clean step, writes a handoff, and carries on with the same task on another of your accounts.

cargo install --git https://github.com/snehal96/anchorleg anchorleg

How it works

What happens when an account runs low

anchorleg starts the official CLI (claude, codex or agy) for you and reads its event stream. Inside Claude Code, a small mod reports exact usage and knows where it is safe to stop; Codex quota is read live before every launch.

  1. Watch

    Every account's 5-hour and weekly windows, from the CLI's own rate-limit events and the mod's exact percentages.

  2. Pause at 90%

    Before the next model request, never mid-edit. Tool results so far are already saved in the session.

  3. Hand off

    .handoff/TASK.md with the goal, steps, files touched and last message, plus a local git checkpoint of the working tree.

  4. Continue

    The next account gets the session and project memory and resumes it. A large context starts fresh from the handoff instead.

You approve what the agent may do

A background run can't show Claude's permission dialog, so anchorleg asks you instead. The session waits until you answer: 1 yes, 2 yes for this session, 3 no.

Same model and effort on every account

One setting per provider, shared by all its accounts, so a task keeps the same strength when it moves. Type /model opus or /effort high in the message box. Your own slash commands and skills pass straight through.

Scriptable

Every command has --json output and stable exit codes, so another program (your own task delegator, a CI job) can run anchorleg as a subprocess.

Ground rules

Built to use your subscriptions the way they're meant to be used

anchorleg switches between accounts you own by relaunching the official CLI. That's all.

  • Official binaries onlyIt starts claude, codex and agy (later cursor-agent) exactly as you would.
  • No token tricksIt never extracts subscription tokens, never calls vendor APIs directly, never runs a proxy.
  • Nothing changed inside a sessionThe mod reads usage and stops at a step boundary. Switching happens outside, by relaunching.
  • Secrets stay in the keychainTokens, when you use them, live in the macOS Keychain. Never in config, logs or test data.
  • Local checkpoints, never pushedCheckpoints are refs under refs/anchorleg/. Your branch, index and stash are untouched.
  • Nothing approved without youTool calls Claude would ask about wait for your answer. No answer in 30 minutes means no.

Get started

Five minutes, if your accounts are already logged in

# 1. install (needs Rust; have claude, codex or agy signed in)
cargo install --git https://github.com/snehal96/anchorleg anchorleg

# 2. add your accounts: import shell aliases like
#    alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'
anchorleg accounts import-aliases --yes

# 3. one model and effort for every Claude account
anchorleg settings claude --model sonnet --effort high

# 4. open the session manager, press n, describe the task
anchorleg ui
